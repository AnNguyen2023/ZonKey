# Dictionary policy and provenance

M2 dictionaries are deliberately small, reviewable, and version controlled:

- assets/dictionaries/en-common.txt contains ordinary English tokens known to
  be distorted by the current Telex composer.
- assets/dictionaries/it-common.txt contains technical and infrastructure
  terms.
- assets/dictionaries/products.txt contains product and platform names.
- assets/dictionaries/never-transform.txt documents protected syntax families;
  executable recognition lives in Rust.

These lists were curated specifically for Zonkey from project requirements and
test cases. No external dictionary dataset was imported. Lines beginning with
a hash and blank lines are ignored. Matching is exact and ASCII
case-insensitive; raw input casing is retained in recovery output.

Additions must include active corpus coverage generated by the real M1 composer
and must demonstrate that raw and rendered text differ. Broad or ambiguous
words should not be added merely to improve recall. Product and technical
entries receive the higher exact-match confidence, but context policy still has
the final say.

DictionaryProvider permits a future adapter to supply a validated local user
allow-list without changing the classifier. M2 provides an in-memory provider
only; it does not read personal dictionaries, persist data, or contact a
service.
